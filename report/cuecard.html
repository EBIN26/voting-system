4. The five key messages (if you forget everything else)

  1. One person cannot change or read the votes.
  2. Each voter votes once: a one-time token, checked in the database and by the contract.
  3. The vote is secret until the election closes: encrypted ballots, with the key split among three trustees (any two decrypt).
  4. The rules are enforced by the smart contract, not by the web server.
  5. Anyone can verify the result by recounting.

5. Limits to state yourself, before she asks

  1. The demo uses dummy voter IDs. A real identity check (such as an OTP) is future work.
  2. In this demo page the server encrypts the ballot, so it sees the voter and the choice together. The full app encrypts in the browser.
  3. Gas on Sepolia (about 1.81 million) is higher than my local figure (about 417,000). We have not explained why.
  4. The trustee passphrases are public in the demo, so the key shares protect nothing in this run.
  5. It is a prototype, with no independent security audit.

Likely questions and short answers

#QuestionShort answer
1Why use a blockchain at all?So that no single person can change the rules or the ballots, and so the public can check them. A normal database gives the administrator that power.
2If the blockchain is public, how is the vote secret?Only encrypted ballots go on it. Each one is 430 bytes and looks random, so its size and content reveal nothing until the trustees decrypt after closing.
3How do you stop someone voting twice?The voter hash is checked against the roll, and each voter gets one token. The database refuses a second token, and the contract accepts each token hash only once.
4What is the voter hash for?The server never stores identities. It stores Keccak-256 of an HMAC of the identity, so even someone who reads the database cannot easily recover the identity.
5Can the server link a vote to a voter?The database has no link: the token table has no voter column or timestamp. But in the demo page the server sees both in one request, so a dishonest server could. The full app encrypts in the browser, and zero-knowledge proofs would fix it fully.
6Why RSA and AES together?RSA can only encrypt small data. AES-256-GCM encrypts the vote quickly and detects tampering, and RSA-3072 protects the AES key.
7Who can decrypt, and when?Any 2 of 3 trustees, together, and only after the election closes. The key is split with Shamir secret sharing, and one share alone reveals nothing.
8Can the administrator cheat?The administrator only opens the election. They cannot read votes, cannot close it early, and cannot change a ballot. The contract does not give that role access.
9What if the cloud server is hacked?It holds only the public key and the backend's submitter key. The attacker cannot decrypt votes or change the rules. They could stop voting (denial of service) or see votes in the demo mode.
10Why is a vote slower on Sepolia?It waits for a real block (7 to 14 seconds). The local chain mines instantly (0.23 s total).
11Why is the gas different (417,000 vs 1.81 million)?We measured both and do not know the cause yet. One possibility is that Sepolia prices new storage differently from my local chain. It is future work to find out and reduce it.
12What did it cost?Nothing: Sepolia test ether is free and the cloud server is on a free tier. On a real network the cost would be gas used times gas price, so it must be measured again.
13Is this ready for a real election?No. It is a prototype. It needs a real identity check, browser-side encryption, several independent submitters, and an independent security audit.
14Where is the ECE content?Cryptography (RSA, AES, hashing, secret sharing), networking (HTTPS, cloud, blockchain network), and secure system design. The hardware is the laptop and the cloud server.
15How did you test it?107 automated tests (20 for the contract, 75 for the backend and cryptography, 12 for deployment), a local election, and a live election on Sepolia with a public recount.
16What about people forced to vote a certain way?An online system cannot prevent coercion away from a polling booth. It is a known limit, listed in the report.
17What was the hardest problem?Two bugs: quick transactions reusing the same number (fixed by turning off the library's cache), and the local chain's clock lagging behind real time (fixed by mining a block first).
18Why did you use Aadhaar OTP before, and not now?The first design simulated an Aadhaar OTP. For the demo we focused on the backend, encryption and blockchain parts. A real identity step is the next layer.
